# The live voice engine

PlaySuite's web build ships no audio files: every sound is generated by code when it is
first wanted. This engine is how. It is the collection's numpy synthesis engine,
`synth.py` (the byte-identical copies in `authoring/audio/work/src/` and
`games/*/audio_src/engine/`), ported to C++20 expression by expression, together with
NumPy's own random numbers, so a game's cue rendered here equals the master its Python
script wrote: to about 1e-14 of full scale, and to the same 16-bit samples as the shipped
WAV. A game lists its cues; the shell renders each one on its loader Worker the first
time it is played and keeps it in memory. Standard library only; no GUI.Forms in the core.

## Files (`src/`)

| File | What it holds |
|---|---|
| `voice_random.hpp` | `Generator`: `np.random.default_rng(seed)` exactly (SeedSequence, PCG64, NumPy 1.26's ziggurat normal and exponential, 53-bit doubles, Lemire integers with the 32-bit half buffer, Poisson, choice). `GeneratorState` is `bit_generator.state`; `advance(n)` skips draws. |
| `voice_random_tables.hpp` | NumPy's 256-entry ziggurat tables, copied exactly from the compiled module. |
| `voice_fft.hpp` | `fft`, `rfft`, `irfft` of any length with NumPy's conventions (mixed radix; Bluestein inside it for a prime factor above 61; recent tables and kernels cached). |
| `voice_synth.hpp` | synth.py: `mtof`, `tarr`, `gate`, `fft_filter`, `partials`, `wavetable`, `pan_gains`, `LoopMix`, `make_ir`, `conv_reverb`, `pingpong`, `autopan`, and `Synth`, one imported module: its `_rng`, every INSTR instrument and DRUMS drum (batch 2 included), `wt`, `noise`, `render_note` / `render_drum` with synth.py's quantised caches. Also the numpy semantics the ports need (`linspace`, `remainder`, pairwise `sum`, `standard_deviation`, `interpolate`, `cumulative_sum`, `python_round`, `samples` = `int(x * SR)`) and the cue-script helpers every `make_sfx.py` repeats: `master` (its `write()` before quantisation), `resonator`, `pcm16`. |
| `voice_bank.hpp` | `Cue` (a name and a renderer of its master in doubles, mono or stereo), `Bank::shared()`, `render(cue)` to interleaved floats. |
| `voice_reference.hpp` | Reading NumPy reference renders and measuring a render against one (tests only). |
| `tools/numpy_reference.py` | Renders the references with NumPy (`engine` and `cues` modes). |
| `tools/score_reference.py` | References for a whole sound script whose `write()` takes a path (music loops, stingers, Koi-Koi's effects): every float master it writes, mono or stereo, the generator states at each, and the `render_note` cache entries a later cue reuses (for `Synth::prime_note`). |
| `tests/voice_tests.cpp` | CTest `voice_engine`; `--reference DIR` compares everything. |

## How a sound reaches the speaker

`src/audio_loader.cpp` (`games::load_audio_clip`) is the one place every PlaySuite player
gets a clip: `PcmPlayer` (and so `SceneAudio`, the shell's `sound_play`/`music_play`
fallback and the ambient `SoundDesk`) and `fourpegs_audio`. Before it looks for
`assets/audio/<name>.ogg|.wav` it asks `voice::Bank::shared().find(name)`. A cue is
rendered on the loader's GUI.Forms Worker, wrapped with `gui_forms::AudioClip::copy`
and kept by name for the life of the process; a second request is answered at once. The
player then treats it exactly as a file: gain, pan, rate, looping, buses and pausing all
apply. Nothing else in the shell changes, and a name with no cue still falls back to its
file, so a game can be converted cue by cue.

A mono master plays as left = right at the master's level, which is what
`ffmpeg -ac 2` did when the runtime files were prepared from the mono WAVs.

## API a game uses

```cpp
#include "voice_bank.hpp"

namespace xx {
namespace {
// what tools/numpy_reference.py printed for the cue: synth._rng where the script began it
constexpr voice::GeneratorState chirp_start{{0x..ull, 0x..ull}, {0x..ull, 0x..ull}, false, 0u};

voice::Signal chirp() {                       // one cue, as the script computes it
    voice::Synth synth(chirp_start);          // `import synth` with _rng at that state
    voice::Generator rng(state_or_seed);      // the script's own default_rng, if it uses one
    const voice::Signal y = synth.render_note("ping", 88, .1, .35);
    ...                                       // the script's lines, in numpy's order
    return voice::master(y, -14);             // its write(name, x, -14)
}
constexpr voice::Cue cues[] = {{.name = "xx_chirp", .mono = chirp}};
}  // namespace
void register_sound_cues() { voice::Bank::shared().add(cues); }
}  // namespace xx
```

Call `register_sound_cues()` from the game's module `create` function (Pen the Sheep:
`games/penthesheep/module.cpp`), before any sound is played.

## Converting a game

Pen the Sheep is the worked example: `games/penthesheep/src/sheep_cues.cpp` (its
`audio_src/make_sfx.py`, 13 cues) and `tests/sheep_cues_tests.cpp`.

1. **Engines.** Add `"voice"` to the game's `GAME.json` `engines`, link `voice_core` from
   its core library in `build.cmake`, and compile the cue file with
   `-ffp-contract=off` (as Pen the Sheep's `build.cmake` does): a fused multiply-add
   changes the last bits, and the ports rely on numpy's exact arithmetic.
2. **Reference renders and start states.** On the Mini (NumPy 1.26 is `/usr/bin/python3`;
   `m4web` does not mirror `audio_src/` or `assets/audio/`, so copy the script folder and
   the game's masters to a scratch folder first):
   ```sh
   /usr/bin/python3 shared/voice/tools/numpy_reference.py cues \
       --script games/<id>/audio_src/make_sfx.py --out /tmp/<id>-ref --masters <masters folder>
   ```
   It runs the script with `write()` intercepted and prints, for every cue, the state of
   `synth._rng` and of every generator in the script's globals at the moment the script
   began that cue, as `voice::GeneratorState` literals; whether the script's `write()`
   normalisation is the standard one (`--fade` and `--fade-in` select a variant: Maze
   fades 0.005 s, Four Pegs has no fade-in, i.e. `--fade-in 0`); and whether each NumPy
   render quantises to the shipped master (it does for Pen the Sheep, byte for byte).
   It also lists any `render_note` cache entries made before a cue; prime those with
   `Synth::prime_note(inst, m, dur, vel, state)` so the cue draws what the script drew.
3. **Port each cue** into a function returning its float master. Write numpy's order of
   operations literally: Python evaluates `a * b * c` as `(a * b) * c`, combines scalars
   before they meet an array (`2 * np.pi * f * t` is `((2 pi) f) t`), and `t` is
   `i / 48000.0`, not `i * (1 / 48000.0)`. `int(x * SR)` is `voice::samples(x)`;
   `np.linspace`, `%`, `np.std`, `np.cumsum` and `round` have exact equivalents above.
   Use the script's own generator objects in the same call order (`rng.uniform`,
   `rng.integers`, `rng.choice` ...). A cue made from two scripts' state (a loop of
   variants, a buffer shared by two cues) gets the state printed for its first write.
4. **Register** the cue table under the names the game plays (`_0N` variants included)
   and call it from `module.cpp`.
5. **Test.** Add a `<id>_cues` test like Pen the Sheep's: without arguments every cue
   renders at its master's length and level; with `--reference DIR` every cue must be
   within 1e-9 of the NumPy float master and quantise to the same 16-bit samples.
   Run it natively and under Node (below), then delete the reference folder.
6. **Then** the game's audio files can leave the web package (a separate change).

Music written on synth.py (`*_music.py`, `LoopMix` and `conv_reverb` loops) converts the
same way; render the stereo bus mix and register it with `.stereo`. A long loop takes
seconds to render and tens of megabytes to keep (a 96 s stereo loop is 37 MB of floats),
so consider rendering it at game open or streaming it through a `games::LiveScore`
generator instead. The generators that are not synth.py (`authoring/playsuite_music`,
`authoring/eggy`, `gnome_voice.mjs`, Switchbox's delivered script) need their own ports;
`Bank` and the loader path serve them unchanged.

## Verifying

```sh
# NumPy references for the engine (on the Mini; about 150 MB, delete afterwards)
/usr/bin/python3 shared/voice/tools/numpy_reference.py engine --synth authoring/audio/work/src/synth.py --out /tmp/voice-ref
# native
.build/<build>/voice_tests --reference /tmp/voice-ref
# the browser toolchain under Node
PLAYSUITE_WEB_NAME=web-voice M4WEB_TOOLKIT=0 tools/web/m4web -- sh tools/web/mini-build.sh voice_tests
node .build/web/voice_tests.js --reference /tmp/voice-ref
```

Measured 2026-10-23 against NumPy 1.26.4 on the Mini, natively (arm64). Under Node
(Emscripten) every random stream is still bit for bit and every render passes, but
musl's libm differs from Apple's in the last bit, so the "bit for bit" audio rows become
≤ 3e-13 of peak (the electric piano is the largest) and Pen the Sheep's cues ≤ 1.9e-14,
still quantising to the shipped WAVs exactly.

| Part | Agreement |
|---|---|
| Random streams: raw, standard_normal (200 000 per seed), random, uniform, exponential, integers (32- and 64-bit ranges), poisson (both methods), choice, a mixed interleaving, `bit_generator.state` | bit for bit |
| `np.sum` / `np.std` (pairwise in 8192-sample buffers) | bit for bit |
| Instruments without filtering: celesta, ep, glass, harp, kalimba, musicbox, ping, synthbass, vibes; drums clave, rainstick, stone, tick, triangle, wbhi, wblo; every wavetable | bit for bit |
| Instruments with a short filtered noise burst: bass, litho, logdrum, marimba, pizz, pluck; kick, rim, logkick, loghi | ≤ 4e-16 of peak (over 99 % of samples identical) |
| Filtered throughout (pad, flute, clarinet, reed, slide, tuba, analog, felt; tap, shaker, hat, clap, brush_swish), `fft_filter`, the mix helpers | ≤ 3e-15 of peak (error about -300 dB) |
| Pen the Sheep's 13 cues | ≤ 1.7e-14 of peak; every cue quantises to the shipped WAV exactly |

The only differences are the Fourier transform's rounding (this FFT is not pocketfft)
and, in the browser, libm's last bit; both sit 280 dB or more below the signal.
The tests' tolerance is 1e-9 of peak.

## Cost

One note renders in 0.4 to 16 ms natively on an M-series Mac (felt piano and harp are the
dearest; anything through `fft_filter` pays for a transform of the note plus 4096
samples). Pen the Sheep's 13 cues together take about 0.13 s. Rendering runs on the
loader Worker, so the first play of a cue starts that much later; every later play is
immediate.

## Limits

- Python's `stone_click`/`rainstick` with `seed=None` draw fresh entropy; here they need a
  seed (render_drum always passes one).
- Clips are kept until the process ends; nothing evicts them.
- `write_wav`/`read_wav` are not ported; the runtime needs neither.
